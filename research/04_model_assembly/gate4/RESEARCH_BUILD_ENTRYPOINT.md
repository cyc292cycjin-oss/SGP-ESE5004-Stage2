# Reproducible Gate4 build entry points

The independent DAG is workflow/research_assembly.smk. A source-path JSON supplies only existing frozen reference/cost/plant/port/airport inputs. It does not ask users to produce electric_base, carrier_fragment or carbon_component_map manually.

```sh
snakemake -s workflow/research_assembly.smk --cores 1 --scheduler greedy --configfile <source_paths.json> --dry-run
snakemake -s workflow/research_assembly.smk --cores 1 --scheduler greedy --configfile <source_paths.json> -- research_build_production_assets
```

The first default target is the guarded complete-network build. Current incomplete scientific inputs prevent that target from exporting a network. Use the explicit asset target to reproduce the delivered development assets. No rule includes the upstream solver or final_adjustment.

Existing-stock evidence is generated by scripts_project/trace_asset_survival.py from frozen PPM IDs and cached GEM sheets. scripts_project/asset_survival.py enforces observed/committed/optimised/new/unknown identity, verified dates and the strict retirement boundary. The present raw ledger has no fully qualified survivor; activation additionally requires accepted numerical lifetimes, raw-to100-node mapping and existing performance/O&M. This is an explicit remaining qualification/integration requirement, not an invitation to use grouped dates.

Production merging preserves static AND time-dependent inputs. Future optimisation must install assembly_components.install_research_constraint_hooks after variable creation; this includes one-way finite stores, annual source caps and paired battery inverter capacities. NetCDF stores identifiers/data for these hooks, not Python callable objects. No optimisation was invoked here.
