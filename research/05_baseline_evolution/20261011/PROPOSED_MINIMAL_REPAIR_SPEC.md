# Proposed minimal source closure repair specification

**版本：EXACT_SOURCE_CLOSURE_A_MAX_ACCOUNT_V1_DRAFT**。

状态：**PROPOSED / AWAITING_USER_AND_CHATGPT_SCIENTIFIC_APPROVAL**。这是独立新版本的变更规范，不是可启动的生产入口，也不是正式输入。旧冻结数据、A03证书、Gate5/Gate6和P2结论、消费标记永久保留；G6-05继续暂停。

## 1. 待批准的唯一原则

权威次序：批准Load的实际binary64位与权重 > 从该Load派生的有限资源Q表示。原始统计、商品/节点/年份归属、各项科学假设、NULL价格、物理CO₂因子和固定终端核算边界保持。选定A，仅在精确D>Q时修订一项派生Q。

需用户明确接受的科学差异：

- 180账户拟上调，合计`45046859/281474976710656≈1.600385921563e−7 MWh`；不是“没有改变资源常数”。
- 最大组内商品份额绝对变化约1.775575033016e−16；科学份额参照不变，实装份额并非逐位不变。
- 全组严格保证D≤Q′，不保证D=Q′。本版最大总余量9.816722013056e−8 MWh，合计2.877903736275e−7 MWh；这包含原205负差组的未变余量。
- 不增加松弛/免费供应组件、不允许负库存，不把未知资源价格改成零。有限舍入余量与精确可行域改变完全公开。

若“逐商品必须严格耗尽Q”或“实装份额完全不变”是额外科学要求，本规范不能据称已满足，须退回共同量化方案审议。不得靠放宽V4处理。

## 2. 输入锁和确定性算法

输入应从既有审核JSON与冻结源记录核身份，冻结GroupID、LoadID、StoreID、MeterID、SourceRow、各double hex与权重。不得仅凭文件名或约等。

1. 在有理数域计算`D=Σ_t Fraction(w_t) Fraction(d_t)`、`Q=Σ_i Fraction(q_i)`。当前385组为`D=8760 Fraction(d)`。
2. 若`D≤Q`，逐位保留所有Q及Load。
3. 否则选q最大的账户，并列取完整资产ID的Unicode码点最小者。精确目标`y=q_j+(D−Q)`。
4. 取最小有限binary64 `q'_j≥y`。用前一可表示数验证`Σ_{i≠j}q_i+prev(q'_j)<D≤Σ_iq'_i`。
5. 其余q、所有d、权重及拓扑不变。输出逐项hex、精确Δ、ULP数、份额差、总余量及责任源行。

“最小”仅限此一个确定账户、其余不变的类别。不得改选小商品来隐藏相对偏差、循环试调或运行优化器挑选分配。本版输入的ULP变化为1–7，不把这一观测自动推广为未来输入的许可上限。

输入异常即停止：组/商品数量变化、NULL/非正Q、非平坦Load或权重变化、源归属冲突、double无穷/下溢、出现本稿未列差异、scope变更。新数据超出这份385组改变量清单时须重新核算并审批，不能把`ceil`当作任意扩大Q的通行证。

## 3. 未来实施应同步的字段（本轮均未改）

拟从源派生阶段修复，**不能只修改LP行界、只修NetCDF或只修验收器**。

| 字段/接口 | 应保持的一致关系 |
|---|---|
| 组件Store初值/容量 | `e_initial=e_nom=q'_i`逐位相同；非循环、零损耗、e_min=0/e_max=1及discharge_only不变 |
| source recipe/routes | `annual_cap_mwh=q'_i`，保留SourceRow/InputID/commodity，不覆盖原q；原值另存原始引用 |
| 导出固定账 | `external_pending_fixed_accounts.QuantityMWh=q'_i`，与Store和route匹配，生成新fingerprint |
| 科学原件 | 原registry、BASE_RECONSTRUCTION、原allocation和旧模型保持；新增带ParentSHA与RepairVersion的受控派生版本 |
| Load和时段 | arrays及权重逐位保持，DemandOwner/exactly-once、2920×3及2050归属不变 |
| 物理LP | 原方程、索引/端口和系数结构不借机改动；新源身份只允许白名单内的Q相关初值/上界差异 |
| 验收/证据 | V4公式、门槛和NULL语义不改；将源ΔQ、有限余量与解残差分列。不能给旧运行事后PASS |
| 特殊范围 | 5项Animal waste本方案变化0；原批准记录保留。若生成过程中出现非零变化或新商品，立即阻断 |

Q由Load派生不等于未来可无限用需求填补现实资源短缺。本次仅限已证明的表示级不闭合，807账户仍不能独立证明真实资源潜力或可持续供应。

## 4. 不产生新不一致的最低验证要求

以下是**批准实施后的验证规范**，本轮未构建新模型，不提前声称通过。

1. **身份/差异白名单**：新输入版本、父SHA、修复方法SHA、全部385/807对账；Load、资源归属、价格/成本、效率、容量类型、CO₂政策无非预期变化。原V3目标是否位级相同须由实际新目标差异核验，不以本设计代替。
2. **全部源常数精确检验**：不是float sum或isclose；逐组`D≤Q′`、前一double最小性、所有Δ/份额均等于已批准清单，所有未改值位级相同。原证书组需确认不再有原来的正RHS。
3. **字段闭合及全部前缀**：初值、上界、route、导出账单一致；各组Load/meter/Store独占性、方向及损耗不变。按已核拓扑，局部解析轨迹`p_i=q'_i d/Q′`给出年度和任意前缀非负库存的存在性检查；这不是完整模型可行证书。
4. **数学系数验证**：在未来另行批准的生成流程内，核所有相关动态、Bus、库存界实际LP值；源常数→D/R→LP边界必须精确相符。幂二乘除需检查有限性、无下溢精度损失及有理数round-trip，禁止通过新缩放掩盖差异。
5. **输出回读**：受控派生NetCDF/JSON逐位回读相关常数，逐文件SHA，独立校验器从导出文件再算。保持旧证书和全部历史矩阵原件，不替换旧文件。
6. **有限审查的结论边界**：通过以上仅消除这一年度源表示矛盾，不证明其他约束无冲突，不保证数值收敛、OPTIMAL或Gate6 PASS。

不能为了通过某项核对修改V4、截断负库存、增加自由输入端口、引入补供/弃供变量或把非零差当成零。本版不授权求解。

## 5. 日模型与全年的一致性

采用同一年度闭合登记而不是随时间分辨率重新浮点积分生成Q。对当前恒定Load，365×24与2920×3都精确为8760小时，所以A的新Q登记可在两个表达中保持一致；没有日模型构建/求解发生。若将来变成非平坦时序、代表日或其他权重，应先按该模式实际存储常数核查，不能外推本结论。
