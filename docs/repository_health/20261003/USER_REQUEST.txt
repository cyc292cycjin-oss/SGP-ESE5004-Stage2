Failure occurred after approximately 2m54s.

Before Phase 4 Full-SC Assembly starts, perform a bounded GitHub/repository health audit.

DO NOT modify the scientific model, research data, assumptions, configs, or Phase1-3 results as part of this task.

Goal:

Determine whether:

A. the repository itself is healthy and usable;
B. the CodeQL workflow alone is misconfigured;
C. there is a permissions / Actions / security-scanning issue;
D. there is a genuine Python/code problem causing CodeQL setup or analysis to fail.

Do not guess from the email notification.
Inspect the actual GitHub Actions failure logs.

- combine unrelated fixes

--------------------------------------------------

--------------------------------------------------
4. Python-specific CodeQL audit
--------------------------------------------------

The failing job is:

Analyze (python)

Verify whether the Python configuration is appropriate.

Check:

- `languages: python`
- whether an unnecessary manual build/autobuild configuration exists
- whether CodeQL is trying to build something that Python analysis does not require
- whether repository Python files are discoverable
- generated/vendor directories
- virtual environments accidentally committed
- very large generated research directories
- archived source snapshots
- notebooks/scripts handling
- malformed Python files if CodeQL explicitly reports them

Do NOT refactor research Python merely to make CodeQL green unless the log proves a genuine source syntax/error issue.

--------------------------------------------------
5. Permissions and code-scanning audit
--------------------------------------------------

Check repository/workflow permissions.

At minimum inspect whether workflow needs/has appropriate:

contents: read

security-events: write

and any other permissions actually required by the run.

Check whether the failure is related to:

- SARIF upload
- GitHub Advanced Security / code scanning availability
- Actions permissions
- workflow token restrictions
- pull-request/fork security restrictions

Distinguish:

analysis succeeded but upload failed

from:

analysis itself failed.

--------------------------------------------------
6. Repository health audit
--------------------------------------------------

Independently of CodeQL, verify repository usability.

Check:

- clone/fetch succeeds
- Git object integrity if appropriate
- default branch exists
- no unresolved merge conflicts
- no invalid Git submodule state
- Git LFS state if used
- branch refs healthy
- workflow YAML parses
- repository size / very large tracked files
- accidental generated artifacts
- zip/pdf/netcdf/raw-data tracking issues
- `.gitignore`
- `.gitattributes`

Do NOT delete large research evidence automatically.

If a file should not be tracked:
report it first.

Remember:
historical provenance files and evidence may intentionally exist in Git.

9. Minimal fix policy
--------------------------------------------------

If root cause is clear and mechanical, e.g.:

- deprecated GitHub Action version
- incorrect permission
- invalid CodeQL language config
- broken workflow syntax

create ONE isolated branch, for example:

Make the smallest possible fix.

One logical problem = one commit.

Suggested commit naming:

Do not mix:

+
research model changes
+
data changes

in the same commit.
